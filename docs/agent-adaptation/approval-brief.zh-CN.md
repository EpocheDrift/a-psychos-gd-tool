## 你现在实际在批准什么

批准后，代表你接受：

1. Agent 通过受限 MCP 和语义命令操作现有节点图，而不是模拟鼠标拖小插口。
2. 普通编辑使用原子事务、revision 冲突检查、request ID 幂等和安全 revert。
3. Agent 可以读文档、改图、上传受限素材、渲染和查看预览。
4. 这个设计 MCP 本身不新增或转授文件系统、任意 URL、shell、任意
   JavaScript、浏览器 CDP/导航和整项目替换能力；Codex、Claude Code 等宿主
   原本拥有什么权限，继续由各自的沙箱和用户批准策略管理。
5. v1 的目标是“可靠执行受限设计工作流”，不是“自动成为完整美术总监”。

这次批准**不代表**：

- 批准立即合并或发布；
- 批准 RMBG-1.4 用于商业场景；
- 批准云端多人或多租户 Agent 服务；
- 承诺所有浏览器、GPU 和操作系统上的像素完全一致；
- 承诺 Agent 已具备无边界的自主审美或自然语言设计能力。

## 需要你拍板的 4 个决定

### 决定 1：v1 能力范围是否够用

当前范围：

- 能发现节点、参数和 typed sockets；
- 能一次创建并连接多节点图；
- 能等待指定 revision 的真实渲染；
- 能看预览和可量化图像指标；
- 能处理人工冲突、错误连线、渲染失败和响应丢失。

我的推荐：**接受。**

原因：这已经构成一个可实际使用的 Agent 控制面。更高阶的自动排版模板、
subgraph duplication 等 helper 暂时没有真实 trace 证明值得扩权。

### 决定 2：是否接受“窄 MCP、宿主权限另管”的边界

这里必须区分两层权限：

1. **宿主 Agent 的权限**：Codex 或 Claude Code 可能本来就有 shell、工作区
   文件、网络或其他浏览器工具。这些权限来自运行它们的宿主环境和你的批准，
   不由本项目授予，也不由本项目撤销。
2. **Graphic Design MCP 的权限**：这个 MCP 只提供经过 allowlist 的设计工具，
   例如读文档、提交事务、等待渲染、获取预览和管理受限素材。它不会把一次
   设计连接变成 shell、通用文件系统、任意网络、CDP 或任意页面执行入口。

换句话说，我们保证的是：

- 连接这个 MCP 不会让一个原本受限的 Agent 获得新的通用系统权限；
- 文档内容或 prompt 不能通过 MCP 自己提升 scope；
- Agent 不能借 `gfx_*` 工具读取任意本地文件、访问任意 URL 或控制整个浏览器；
- 设计应用内部只接受版本化、校验过的命令。

我们**不保证**：

- Codex 或 Claude Code 在它自己的宿主环境里没有 shell；
- 宿主已经授予的文件/网络权限会被这个 MCP 收回；
- 一个同时拥有其他强力工具的 Agent 只能通过本 MCP 行动。

如果需要“Agent 只能使用设计 MCP”，还必须在 MCP 之外把宿主 Agent 放进
独立 sandbox/container，只给它这个 MCP 连接。那属于部署策略，不是本项目
自身可以完成的安全边界。

我的推荐：**接受，先不要放宽。**

原因：现有三类创作任务都能通过这个窄 MCP 一次原子完成。等真实使用出现
明确阻碍，再针对单一设计能力增加窄工具，比在 MCP 内加入通用 shell、文件
或浏览器控制更容易审计。宿主 Codex/Claude Code 是否可以同时使用其他工具，
应作为另一项运行时权限决策单独管理。

### 决定 3：RMBG-1.4 的 A 路线是否继续

当前约束：

- 模型只能走固定、校验过的本地缓存；
- 首次下载需要独立的人类许可确认；
- Agent 看不到模型 URL 或文件路径；
- 当前披露要求商业使用另行获得协议。

我的推荐：**继续 A 路线，但把它明确标为非商业/内部试用能力。**

如果下一阶段要商业发布，模型许可必须成为独立发布门，不应由本次代码审批
顺带放行。

我的推荐：同时满足下面两项后再改：

- [ ] 你亲自完成一次 Web UI + Agent MCP 实操验收；

在这之前，建议继续保持 Draft。现在没有技术 blocker，但仍缺“产品手感”和

## 下一次实操验收建议

建议把实操拆成两个独立 session，不和代码 review 混在一起。

### Session A：人类 Web UI，约 15–20 分钟

1. 打开现有项目，修改文字、颜色和 frame。
2. 新增/连接几个节点，测试 Undo/Redo。
3. Save Project，再 Load Project。
4. 上传一个真实素材，确认保存、重开和预览均正常。

通过标准：

- 没有数据丢失；
- 原有人类编辑手感没有明显变差；
- 保存/载入和 Undo/Redo 符合预期；
- 错误提示能让人理解下一步怎么处理。

### Session B：Agent MCP，约 20–30 分钟

建议实际做三个贴近使用的案例：

1. **海报标题**：让 Agent 创建 Text → Outline → Warp → Rasterize →
   Recolor → Output，并根据预览再改一次颜色或弯曲程度。
2. **环形字标**：让 Agent 用 Split + Math Function + Place 做一个环形
   文字构图，再要求它调整半径和字距。
3. **人机交替编辑**：Agent 先读取并规划；你在 UI 中临时改一个 layer 或
   frame；再让 Agent 继续，确认它会重新读取而不是覆盖你的修改。

可选第四例：

4. **真实素材/去背景**：在你明确接受模型许可后，上传自己的图片并运行
   Remove Background；检查模型权限、失败提示和恢复流程。

通过标准：

- Agent 不需要鼠标坐标或内部 store；
- 结果可见且不是空白；
- 第二轮修改基于当前 revision；
- 人工插入修改不会被覆盖；
- 出错后 Agent 能解释并继续，不需要重启整个项目。

这两次 session 的观察结果应单独记录为“产品验收证据”，不要塞进技术测试
日志。届时再决定是否需要新增 helper、调整权限或修改默认工作流。
